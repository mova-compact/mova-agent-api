# 06. Telegram как операторская консоль

Этот раздел объясняет, как использовать Telegram как рабочий интерфейс оператора.

## Зачем Telegram используется

Telegram нужен, чтобы оператор мог:

- видеть команды;
- получать отчёты;
- получать запросы на подтверждение;
- быстро проверять состояние системы.

## Что оператор видит в Telegram

Оператор видит:

- кнопки;
- краткие статусы;
- результаты запусков;
- запросы на подтверждение;
- сообщения о проблемах.

## Что Telegram может делать

Telegram может:

- показать текущий запуск;
- показать последний результат;
- дать кнопку подтверждения;
- показать журнал или ссылку на него;
- дать быстрый вход в настройки.

## Чего Telegram не должен делать

Telegram не должен:

- быть источником власти;
- хранить секреты;
- подменять политику;
- принимать решение вместо системы;
- подтверждать действие без связи с конкретным запуском и журналом.

## Что означает каждая кнопка

### ▶️ Запустить отчёт

Назначение:

- запустить отчёт вручную.

Когда используется:

- когда оператор хочет проверить процесс сейчас, не дожидаясь расписания.

Норма:

- появляется новый запуск;
- видно, что процесс стартовал.

Настораживает:

- кнопка сработала, но запуск не появился;
- результат пришёл без понятного идентификатора.

### 📊 Последний запуск

Назначение:

- показать последний результат и его статус.

Когда используется:

- для быстрой проверки состояния системы.

Норма:

- виден понятный последний итог;
- статус совпадает с журналом.

Настораживает:

- статус непонятен;
- результат расходится с журналом.

### ✅ Одобрить

Назначение:

- подтвердить безопасное продолжение.

Когда используется:

- если система остановилась и ждёт человека.

Норма:

- решение привязано к конкретному запуску;
- после подтверждения видно продолжение.

Настораживает:

- кнопка доступна без контекста запуска;
- предлагается подтвердить без объяснения.

### ⛔ Отклонить

Назначение:

- остановить спорный или небезопасный процесс.

Когда используется:

- если данные ненадёжны;
- если результат выглядит рискованно;
- если оператор не уверен.

Норма:

- запуск останавливается безопасно;
- причина отказа остаётся в следе.

Настораживает:

- отклонение не фиксируется;
- система продолжает как будто ничего не произошло.

### 🧾 Журнал

Назначение:

- открыть журнал выполнения.

Когда используется:

- когда нужно понять, что случилось на самом деле.

Норма:

- журнал читается;
- видно последовательность действий.

Настораживает:

- журнал пустой;
- журнал не связан с запуском;
- причина ошибки скрыта.

### ⚙️ Настройки

Назначение:

- перейти к рабочим параметрам системы.

Когда используется:

- при проверке среды и рабочих настроек.

Норма:

- видно, что настройки относятся к правильному контуру.

Настораживает:

- есть риск перепутать тестовую и рабочую среду;
- видны данные, которые не должны показываться в Telegram.

### ❤️ Проверить здоровье системы

Назначение:

- быстро понять, жива ли система.

Когда используется:

- перед запуском;
- в начале дня;
- при подозрении на сбой.

Норма:

- система отвечает;
- базовые проверки проходят.

Настораживает:

- здоровье не проходит;
- система молчит;
- ответ есть, но он противоречит остальному состоянию.

## Главный принцип Telegram

- Telegram — интерфейс оператора;
- Telegram — не источник власти;
- Telegram не должен хранить секреты;
- подтверждение через Telegram должно быть связано с конкретным запуском и журналом.

## Будущий скилл Codex

### `mova-telegram-operator-maintainer`

Назначение:

- поддерживать операторское Telegram-меню и связанные тексты.

Вход:

- список кнопок;
- сценарии запуска;
- правила подтверждения;
- требования к безопасности.

Выход:

- понятное Telegram-меню без секретов и без двусмысленности.

Проверки:

- кнопки понятны оператору;
- действие связано с конкретным запуском;
- секреты не показываются;
- подтверждение нельзя использовать без контекста.

Запреты:

- не класть секреты в Telegram;
- не делать Telegram источником решения;
- не размывать смысл кнопок;
- не показывать рабочие данные там, где им не место.
