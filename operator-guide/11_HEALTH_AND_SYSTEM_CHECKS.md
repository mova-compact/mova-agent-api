# 11. Проверка здоровья системы

## Operator Consistency Rule

Каждая проверка отмечена:

- `Реальное поведение (verified)`;
- `Частично подтверждено (partially verified)`;
- `Ещё не реализовано (not implemented)`.

## Что такое health check

Health check — это быстрый ответ системы на вопрос “контур жив?”.

`Реальное поведение (verified)`:

- `GET /health` отвечает и показывает, что сервис жив;
- `GET /ready` показывает готовность по базовым зависимостям.

## Что оператор проверяет утром

1. `MOVA API` отвечает на `/health`.
2. Контур готов по `/ready`.
3. Доступен базовый маршрут `/capabilities`.
4. Есть доступ к списку контрактов `/contracts`.
5. Виден последний статус интересующего запуска через `/runs/{run_id}`.
6. Проверена очередь ожидающих подтверждений по текущим `run_id`.

## Признаки “система жива”

- `health` отвечает `status=ok`;
- `ready` отвечает `ready=true`;
- базовые маршруты читаются без аварий;
- запуск/чтение журнала выполняются в ожидаемом режиме.

## Признаки “контур повреждён”

- `health` недоступен;
- `ready=false` или зависимость в ошибке;
- запускам не хватает доказательств;
- повторяется один и тот же отказ без изменения входа;
- контекст запуска теряется между критичными шагами.

## Будущий скилл Codex

### `mova-health-check-runner`

Назначение:

- запускать и сводить ежедневные проверки здоровья контура.

Вход:

- среда;
- базовый URL;
- список обязательных маршрутов;
- контрольные `run_id`.

Выход:

- короткий health-отчёт: что живо, что частично, что сломано.

Проверки:

- маршруты `/health` и `/ready` отвечают;
- чтение контрактов доступно;
- чтение статуса и доказательств доступно;
- нестабильные места отмечены отдельно.

Запреты:

- не скрывать частично рабочие участки;
- не называть “зелёным” контур без проверки доказательств;
- не подменять runtime-факт архитектурным ожиданием.
