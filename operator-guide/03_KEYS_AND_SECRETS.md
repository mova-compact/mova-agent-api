# 03. Ключи и секреты

Этот раздел объясняет, что такое ключи, где их держать и как не создать утечку.

## Что такое ключ

Ключ — это секретный доступ к системе или сервису.

Он даёт право:

- читать или менять данные;
- отправлять сообщения;
- запускать операции;
- подключаться к внешнему сервису.

## Главные правила

- ключ нельзя показывать посторонним;
- ключ нельзя печатать в логах;
- ключ нельзя класть в открытый GitHub;
- ключ нельзя вставлять в документацию как реальное значение;
- ключ нельзя смешивать между тестовой и рабочей средой.

## Где хранить ключи

Ключи должны храниться в безопасном месте среды, а не в тексте документа.

Для оператора главное правило простое:

- в документации может быть только имя ключа;
- само значение ключа должно храниться отдельно;
- если есть сомнение, считать ключ уже скомпрометированным и заменить его.

## Почему нельзя хранить секреты в GitHub

Потому что GitHub — это хранилище файлов и истории изменений.

Если секрет попадёт в GitHub, он может:

- остаться в истории коммитов;
- стать доступным не тем людям;
- попасть в копии, экспорт или логи;
- создать риск для рабочей среды.

## Что делать при утечке

Если ключ утёк:

1. считать его недействительным;
2. заменить его новым;
3. проверить, где он мог быть использован;
4. проверить, не попал ли он в GitHub, лог или сообщение;
5. убедиться, что рабочая среда снова использует только новый ключ.

## Среды

### Локальная среда

Локальная среда — это твой компьютер.

Она нужна для проверки, сборки и безопасной отладки.

### Тестовая среда

Тестовая среда — это безопасная проверка без клиента.

Она нужна для прогона сценариев без риска для рабочего процесса.

### Рабочая среда

Рабочая среда — это настоящий контур, где сообщения и действия идут пользователю.

Именно здесь ошибка в ключе или Telegram может повлиять на реальную работу.

## Главное правило среды

Не смешивать тестовые ключи, тестовые данные и рабочий Telegram.

Если смешать, можно:

- отправить тестовый результат настоящему человеку;
- сломать безопасность;
- получить ложное ощущение, что всё работает;
- потерять доверие к результатам.

## Перечень ключей

- `MOVA_API_TOKEN` — ключ доступа к MOVA API.
- `TELEGRAM_BOT_TOKEN` — ключ Telegram-бота.
- `TELEGRAM_ALLOWED_CHAT_ID` — разрешённый Telegram-чат.
- `OPENAI_API_KEY` — ключ OpenAI.
- `OPENROUTER_API_KEY` — ключ OpenRouter, если используется.
- `CLOUDFLARE_API_TOKEN` — ключ Cloudflare.
- `GITHUB_TOKEN` — ключ GitHub, если нужен.

## Как смотреть на каждый ключ

### `MOVA_API_TOKEN`

Даёт доступ к `MOVA API`.

Нужен для доступа к самому контуру MOVA.

### `TELEGRAM_BOT_TOKEN`

Даёт доступ Telegram-боту.

Нужен, чтобы бот мог отправлять сообщения и принимать команды в разрешённом канале.

### `TELEGRAM_ALLOWED_CHAT_ID`

Указывает разрешённый чат Telegram.

Нужен, чтобы бот не работал в чужих чатах.

### `OPENAI_API_KEY`

Даёт доступ к OpenAI.

Нужен, если система использует модели OpenAI.

### `OPENROUTER_API_KEY`

Даёт доступ к OpenRouter.

Нужен только если этот провайдер реально используется.

### `CLOUDFLARE_API_TOKEN`

Даёт доступ к Cloudflare.

Нужен для работы с рабочим сервером и связанными настройками.

### `GITHUB_TOKEN`

Даёт доступ к GitHub.

Нужен, если система должна работать с файлами, репозиториями или действиями в GitHub.

## Что оператору важно проверять

- ключ существует;
- ключ не пустой;
- ключ подходит именно для этой среды;
- ключ не попал в GitHub;
- рабочий контур не смешан с тестовым.

## Будущий скилл Codex

### `mova-key-manager`

Назначение: управление ключами.

Вход:

- список нужных ключей;
- нужная среда.

Выход:

- проверенный набор переменных без раскрытия значений.

Проверки:

- ключ существует;
- ключ не пустой;
- ключ не попал в GitHub;
- рабочий контур не смешан с тестовым.

Запрет:

- не печатать секреты в лог;
- не сохранять секреты в документацию.
